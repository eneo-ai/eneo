# Eneo.js

Lightweight and typed JS client for the Eneo backend.

## Usage

```js
import { createEneo } from "@eneo/eneo-js";

const eneo = createEneo({
  apiKey: <token>,
  baseUrl: <baseUrl>,
});

const groups = await eneo.groups.list()
```

Create an `eneo` object with the `createEneo()` function. It provides convenience wrapper functions around the Eneo API.

### Errors

All Eneo functions can throw an `EneoError`, providing a `stage: "JSON" | "HTTP"` and a `request: { endpoint: string; payload?: object; }`, during which the error occured on top of the error's `message`.

## Advanced usage

### Custom fetch function

If you work with a js framework (e.g. SvelteKit) that implements its own fetch function, you can pass it while creating the eneo object like so:

```js
import { createEneo } from "@eneo/eneo-js";

// SvelteKit +layout.js load function
export const load = async (event) => {
  const eneo = createEneo({
    token: event.data.token,
    baseUrl: event.data.baseUrl,
    fetch: event.fetch
  });

  return { eneo };
};
```

### Typed client

You can query the backend directly through the client's typed fetch function, which migh come in handy if you only need a specific endpoint or need to minimise bundle size.

```js
import { createClient } from "@eneo/eneo-js";

const client = createClient({
  apiKey: <token>,
  baseUrl: <baseUrl>,
});

const groups = await client.fetch("/api/v1/groups/", { method: "get" })
```

## Development

Eneo.js is written as pure JS library with typing provided through TsDoc. Types for the backend are autogenerated from the openapi.json.

### Install dev dependencies

```bash
bun install
```

### Update schema

To regenerate the backend types from the configured backend URL, run

```bash
bun run update && bun run lint
```

`bun run update` reads `ENEO_BACKEND_URL`, then `ENEO_BACKEND_URL`, then falls back to `http://localhost:8123`. `bun run update -- --local` forces `http://localhost:8123`.

For reviewable, byte-stable regeneration, first save one backend OpenAPI snapshot and then update from that file:

```bash
cd ../../../backend
uv run python -c 'from eneo.server.main import get_application; import json; print(json.dumps(get_application().openapi(), sort_keys=True))' > /tmp/eneo-openapi.json

cd ../frontend/packages/eneo-js
node update.js --schema-file /tmp/eneo-openapi.json
git diff --stat src/types/schema.d.ts
```

`--schema-file` is mutually exclusive with `--local` and ignores backend URL environment variables. URL mode preserves the backend's raw OpenAPI response ordering; use a saved, canonicalized schema file when a byte-identical diff is required.

Update the endpoints accordingly.
