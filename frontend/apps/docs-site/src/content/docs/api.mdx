# API Reference

Eneo's running FastAPI application is the API contract authority. Its generated
OpenAPI schema and interactive documentation always reflect the routes, request
models, response models, and security requirements in the deployed version.

## Explore a running instance

For a local backend started with the repository defaults, open:

- [Swagger UI](http://localhost:8123/docs)
- [ReDoc](http://localhost:8123/redoc)
- [OpenAPI JSON](http://localhost:8123/openapi.json)

For another deployment, replace the host and port while keeping these root
paths. The reference production proxy routes `/docs` and `/openapi.json` to the
backend alongside the configured API prefix.

## Authenticate deliberately

Endpoints declare their applicable security scheme in OpenAPI. Do not infer a
shared bearer-token format from an endpoint example: Eneo supports browser
sessions and scoped API keys, and authorization depends on the route and the
caller’s tenant and resource permissions.

For API-key creation, rotation, and scope guidance, see
[API Key Management](/docs/api-key-management).

## Use the generated contract

Use the deployed OpenAPI JSON when generating a client or validating an
integration. It is safer than copying endpoint snippets from documentation,
because paths and schemas can evolve with the deployed release.

The repository also exposes the same schema at `/api-docs` under its configured
API prefix for integrations that need an API route to retrieve it.

## Integration support

If an endpoint’s required permission or response shape is unclear, inspect its
entry in Swagger UI or ReDoc first. Report a contract problem through
[GitHub Issues](https://github.com/eneo-ai/eneo/issues).
