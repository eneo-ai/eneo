# Upgrade Guide: Eneo 2.2.0

Eneo 2.2 completes the rename from Intric to Eneo. The old `INTRIC_*`
environment variable names are no longer read, and the API uses Eneo names
throughout. This page lists what to change before you deploy and how to
recognise a deployment that still uses an old name.

import { Callout } from 'nextra/components'

<Callout type="warning">
  **Rename environment variables before you deploy 2.2.** `db-init`, the
  backend, the worker and the web app refuse to start while a renamed variable
  is set without its replacement.
</Callout>

For the rest of the procedure (backups, draining work, File and Icon storage),
follow [Updating Eneo](/guides/deployment#updating-eneo).

---

## Environment variables

Earlier releases accepted the old names as aliases. From 2.2 only the new names
are read.

| Old variable                | New variable              | File               |
| --------------------------- | ------------------------- | ------------------ |
| `INTRIC_SUPER_API_KEY`      | `ENEO_SUPER_API_KEY`      | `env_backend.env`  |
| `INTRIC_BACKEND_URL`        | `ENEO_BACKEND_URL`        | `env_frontend.env` |
| `INTRIC_BACKEND_SERVER_URL` | `ENEO_BACKEND_SERVER_URL` | `env_frontend.env` |
| `PUBLIC_INTRIC_BACKEND_URL` | `PUBLIC_ENEO_BACKEND_URL` | `env_frontend.env` |

`ENEO_SUPER_DUPER_API_KEY` and `INTRIC_SUPER_DUPER_API_KEY` are removed without
a replacement. Module administration happens in **Admin → Modules** by an
administrator with the `modules` permission; see
[Module administration](/guides/deployment#module-administration). Delete the
variable.

The crawler variables of earlier releases are also removed; see
[Retired crawler variables](#retired-crawler-variables).

Find old names in the environment files:

```bash
grep -n -E 'INTRIC_|SUPER_DUPER|TENANT_WORKER_|USING_CRAWL|CRAWL_FEEDER_|CRAWL_STALE_|CRAWL_JOB_MAX_AGE|CRAWL_PAGE_MAX_RETRIES|CRAWL_PAGE_RETRY_DELAY|ORPHAN_CRAWL_' env_backend.env env_frontend.env
```

If you pass variables another way, such as Compose `environment:` entries or a
secret store, check there too.

### What you see at startup

| Situation                                               | `db-init`, backend and worker                   | Web app                                    |
| ------------------------------------------------------- | ----------------------------------------------- | ------------------------------------------ |
| An old name is set and its new name is not              | Does not start; names the replacement           | Does not start; names the replacement      |
| Both the old and the new name are set                   | Starts; warns that the old name is ignored      | Starts; warns that the old name is ignored |
| `ENEO_SUPER_DUPER_API_KEY` or its old name is set       | Starts; logs an error that it is no longer read | —                                          |
| A retired crawler variable differs from its old default | Does not start; names the replacement, if any   | —                                          |
| A retired crawler variable is at its old default        | Starts; warns that it is no longer read         | —                                          |
| `ENEO_BACKEND_URL` is not set                           | —                                               | Does not start; says that it is required   |

A service that does not start logs, for example:

```text
Eneo cannot start while removed environment variables are set:
  INTRIC_SUPER_API_KEY is no longer read (removed in Eneo 2.2). Rename it to ENEO_SUPER_API_KEY.
```

`db-init` runs the migrations, so it is usually the first to stop. With
`docker compose run --rm db-init`, the message appears directly above
`Error running alembic migrations`. Services that restart automatically keep
restarting until the variable is renamed.

### Retired crawler variables

The Python crawler replaced the Scrapy crawler, its Redis feeder and its
per-tenant semaphore. Crawl admission, leases and recovery now live in
PostgreSQL, and these variables are no longer read. One rule applies to all of
them:

- A variable set to a value **different from its old default** stops startup,
  because a value you chose would otherwise be lost. The message names the
  setting that replaces it, or says that it is no longer configurable. Remove the
  variable.
- A variable set to its **old default** only logs a warning. The deployment
  templates shipped these defaults, so a copied template starts as before.

| Variable                              | Old default | Replaced by                                                              |
| ------------------------------------- | ----------- | ------------------------------------------------------------------------ |
| `TENANT_WORKER_CONCURRENCY_LIMIT`     | `4`         | `CRAWL_JOB_TENANT_CONCURRENCY_LIMIT`                                     |
| `CRAWL_FEEDER_INTERVAL_SECONDS`       | `10`        | Nothing: the feeder that paced crawl dispatch is gone                    |
| `CRAWL_FEEDER_BATCH_SIZE`             | `10`        | Nothing: the feeder that paced crawl dispatch is gone                    |
| `USING_CRAWL`                         | `true`      | Nothing: crawling cannot be switched off by environment                  |
| `CRAWL_FEEDER_ENABLED`                | `true`      | Nothing: PostgreSQL dispatches scheduled crawls                          |
| `TENANT_WORKER_SEMAPHORE_TTL_SECONDS` | `39600`     | Nothing: the Redis slot counter it expired is gone                       |
| `ORPHAN_CRAWL_RUN_TIMEOUT_HOURS`      | `12`        | Nothing: stuck crawls are recovered when their PostgreSQL lease expires  |
| `CRAWL_STALE_THRESHOLD_MINUTES`       | `30`        | Nothing: a new crawl no longer preempts an older one of the same website |
| `CRAWL_JOB_MAX_AGE_SECONDS`           | `1800`      | Nothing: queued crawls wait in PostgreSQL admission instead of expiring  |
| `CRAWL_PAGE_MAX_RETRIES`              | `3`         | Nothing: the crawler retries pages by its own policy                     |
| `CRAWL_PAGE_RETRY_DELAY`              | `1.0`       | Nothing: the crawler retries pages by its own policy                     |

The crawler worker takes queued crawls as capacity allows, bounded by
`CRAWL_JOB_CONCURRENCY_LIMIT` and `CRAWL_JOB_TENANT_CONCURRENCY_LIMIT`; there is no
pacing interval or batch size.

To keep crawls from running, leave the `crawler-worker` service stopped (started
crawls then stay queued) and set each website's update interval to Never.

To check a deployment for leftovers:

```bash
docker compose logs db-init backend worker frontend | grep -E 'no longer read|is ignored|cannot start'
```

## API changes for integrations

Clients that call the Eneo API directly must use the new names. The API no
longer uses the old ones.

| Area                       | Before 2.2                     | From 2.2                   |
| -------------------------- | ------------------------------ | -------------------------- |
| Error response field       | `intric_error_code`            | `eneo_error_code`          |
| Streaming event name       | `intric_event`                 | `eneo_event`               |
| Streaming event type field | `intric_event_type`            | `eneo_event_type`          |
| WebSocket subprotocol      | `intric`                       | `eneo`                     |
| OpenAPI schema names       | `IntricEventType`, `intric__…` | `EneoEventType`, `eneo__…` |

The event type field changed on every streaming event that carries it: tool
calls, tool approvals, token usage and image generation. Regenerate clients that
are generated from the OpenAPI schema. The error envelope is described in
[API](/docs/api).

---

## Open browser tabs

Reload open Eneo tabs after the upgrade. A tab loaded before the upgrade keeps
the old app code until it is reloaded: live updates stop, and chat no longer
shows image generation progress or token usage.

---

## Commands and monitoring

If you override the container commands, use the new module paths:

```bash
gunicorn src.eneo.server.main:app
arq src.eneo.worker.arq.WorkerSettings
python -m eneo.cli.<command>
```

Log records use `eneo.*` logger names and worker traces use the `eneo.worker`
tracer. Update log filters, alerts and dashboards that match `intric.*`.

Background jobs queued before the upgrade still run after it.
