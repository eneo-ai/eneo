# Codex Verification Report: Fable 07 v2 Evidence And Legal Transparency

## TL;DR
1. Fable’s core blocker is verified: rerun acceptance destroys the current full step-result evidence for superseded executions, while attempts keep only provenance previews and the attempt payload columns are not written by runtime code.
2. Fable’s model-setting claim is verified: persisted model parameters describe configured assistant kwargs, not necessarily the kwargs actually sent after JSON-mode mutation or fallback retry.
3. Fable’s outbound HTTP/webhook claim is verified with nuance: HTTP request evidence is audit-only and best-effort; webhook delivery rows are durable before purge but are not included in the evidence bundle.
4. The strict export manifest vs debug projection concern is mostly reconciled: there is one export owner; the problem is duplicated weak projections and normalization opacity, not two competing legal surfaces.
5. I did not run Claude, Fable, Antigravity, subagents, internet browsing, test suites, or edits. `[no-peer-review]` because your prompt explicitly forbade peer-loop tools.

## False Positives / Overclaims

- No hard false positives found in Fable’s top claims.
- `artifact_content_purged` is overstated as “no producer” if read as “impossible.” Source can observe the state when both `Files.blob` and `Files.text` are null, and tests synthesize an artifact tombstone. I verified no in-repo mutator creates that state, so this is a defensive/unowned producer issue, not a dead state like `redacted_for_deletion`.
- “Delete `McpProvenance`” needs a narrower wording. Attempt-level MCP invocation provenance has no producer, but the debug projection does expose authored MCP configuration. Delete or hide the empty attempt section only; do not delete MCP config evidence.
- F-4’s “no capture contract” is valid as maintainability debt but inflated if treated as a legal blocker. The top-level provenance envelope has schema versioning, forbidden unknown top-level keys, corrupt markers, and retention markers. The weak part is the internal section shapes.
- F-6’s proposed “manifest-level actors outside the hashed bundle” is not obviously the right canonical shape. An un-hashed actor appendix may create a second disclosure surface. Reuse the presenter, but decide whether actor enrichment belongs inside the hashed bundle, typed summary, or manifest.
- The purge-ledger idea is not a current export bug. After full purge there is intentionally no run export. Whether Eneo must later answer “run X was purged on date D under policy P” is a legal retention decision.

## Confirmed Legal/Disclosure Blockers

1. Rerun evidence loss is the main blocker. A disputed superseded execution can lose its full resolved input, full output, effective prompt, and model parameters from the current step result, while attempts do not preserve full input/output payloads.
2. Sent model settings are not faithfully recorded. JSON-mode mutation and fallback can make the real provider calls differ from exported `model_parameters_json`.
3. Outbound transfer evidence is incomplete. HTTP request details are audit-only and best-effort; webhook delivery rows are not exported and are deleted at run purge.
4. If legal export promises the “original request,” idempotency metadata must either be exported or explicitly excluded. It is persisted today but missing from the evidence bundle.

## Confirmed High-ROI Non-Blockers

- Remove `redacted_for_deletion` and its manifest counter. It cannot validate and makes the retention model look broader than it is.
- Add a redaction scope note. The current redaction policy is acceptable if it clearly says it masks secrets/patterns, not free-text PII.
- Add a provenance normalization note, or move derived values to summary only. Exported provenance is useful but not raw stored bytes.
- Merge duplicate summary/debug derivations and drop the duplicate embedded definition snapshot if the UI does not need it there.
- Fix duration from `created_at`/`updated_at` to `started_at`/`finished_at`.
- Add RAG chunk row id and chunk text hash before inventing a larger RAG evidence model.

## What Not To Fix Now

- Do not add a generic evidence event store or compliance platform. The current attempt table, step results, outbox/delivery rows, and bundle renderer are the right owners to deepen.
- Do not increase the 16 KB preview caps as the main fix. Full superseded payload preservation belongs in attempt payload columns or an explicit not-captured marker.
- Do not build NLP/PII anonymization for redacted exports unless legal/product asks for it. A scope note is the minimal honest fix.
- Do not collapse `debug-export.v2` wholesale. It feeds the typed view response; trim duplication and drift instead.
- Do not create new abstraction layers for capture contracts. Promote the fields the export reads into existing provenance section models.
