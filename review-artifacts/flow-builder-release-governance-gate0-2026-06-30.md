## Stop / Blockers / Risks

- Active abandoned sessions can retain conversation/planning/proposal content indefinitely under current source because only `applied` and `cancelled` are retention-eligible. This is a product/privacy decision, not a bug to patch by guessing.
- Audit rows are intentionally separate from Builder session deletion. Treating audit deletion as part of Builder cleanup would be a compliance risk.
- Global file rows can outlive Builder session links. Current source proves Builder pin removal, not a Builder-specific orphan-file sweep; Gate 1 must accept retention of those rows or name a cleanup owner.
- Repair/fallback pruning is still blocked by real branch-level evidence. C8.14 recorded that unit tests and deterministic goldens are not enough to delete repair branches.
- Do not create new governance, retention, lifecycle, or capability abstractions from this inventory. Existing owners are sufficient for the current policy surface.
