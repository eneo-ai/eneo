# Architecture Decision Backlog

TL;DR:
1. These ADRs are required before or during implementation of the refactor PRDs.
2. Highest priority ADRs cover status lifecycle, terminalization/audit, OpenAPI/generated types, permissions, runtime input mapping, rerun, and human review.
3. Every ADR must include alternatives and why the default is cleaner for this pre-production codebase.
4. ADRs should be written before implementation when they define status, data, API, or runtime behavior.
5. Do not use ADRs to preserve indecision; each one needs a recommended default.

| ADR | Decision | Why It Matters | Alternatives | Recommended Default | Related PRD |
|---|---|---|---|---|---|
| Flow Status Lifecycle Ownership | Where status labels and lifecycle semantics live and how DB/API/frontend projections stay aligned. | Pause, review, rerun, reconciliation, UI controls, and generated types all depend on status semantics. | Enum only; PostgreSQL enum; varchar CHECK; enum plus lifecycle projection. | Enum labels plus lifecycle projection and parity tests before adding new states. | PRD-002, PRD-003 |
| Published Flow Definition Contract | How published definitions are versioned, parsed, rendered, migrated, and corrupted. | Runtime execution and evidence rely on immutable snapshots. | Keep JSON only; add schema_version column; normalize definition tables. | Versioned parser/writer plus first-class schema version; keep JSON snapshot. | PRD-002 |
| Runtime Terminalization And Audit Durability | What happens when run terminalization and audit outbox insert/delivery fail. | Terminal state without durable audit is a support/compliance gap. | Fail open with warning; fail closed before state change; outbox retry. | Outbox row in terminalization transaction; fail before state change if insert fails; retry/alert delivery. | PRD-003, PRD-009 |
| Flow API Type Generation Strategy | Whether generated OpenAPI or handwritten frontend types are canonical. | Frontend status/API drift blocks lifecycle changes. | Handwritten types; generated-only; generated plus aliases. | Fix OpenAPI at source, then generated `schema.d.ts` plus narrow aliases. | PRD-004, PRD-006 |
| Flow Access Policy Actions | How actions are named and enforced for users/service keys/AI Builder sessions. | New endpoints need consistent auth and no raw request scope reads. | String actions; route-local helpers; typed action registry. | Typed `FlowApiAction` policy using `FlowPrincipal`. | PRD-002, PRD-004 |
| Permission Migration From Legacy Flow Aliases | How existing `FLOWS`/`FLOWS_MANAGE` grants map to granular actions. | Default-granting pause/resume/review may expand access. | Map broadly; map minimally; require manual migration. | Minimal explicit mapping with tests; no pause/resume/review grant by default. | PRD-002 |
| Idempotency Retention And Expiry | How long idempotency keys are retained and what old retries return after expiry. | This is a public API retry contract and affects DB indexes/cleanup. | Keep forever; fixed TTL and treat expired key as new; fixed TTL with old-run lookup; no idempotency expiry. | Fixed documented retention; after expiry the key is treated as new unless caller uses run lookup by ID. | PRD-002, PRD-004 |
| Runtime File Mapping Contract | How per-step file inputs are represented and how top-level `file_ids` is deleted. | External API consumers need deterministic file-to-step mapping and operators need attempt-level evidence/debug joins. | Keep top-level `file_ids`; dual shape; canonical `step_inputs`; attempt-scoped relational mapping plus JSON snapshot. | Canonical `step_inputs`; delete top-level request `file_ids`; keep immutable normalized JSON snapshot for idempotency/evidence; add attempt-scoped relational input and output file rows. | PRD-003 |
| Runtime Input/Artifact Relational Extraction | Which runtime facts stay JSONB and which become relational tables. | Over-normalizing creates migration/transaction burden; under-modeling hides lifecycle, audit, retry, permission, and debug facts. | Versioned JSONB; first-class tables; hybrid. | Hybrid: versioned JSONB for heterogeneous payload snapshots; relational rows for file references, rerun operations, review checkpoints, outbox/audit ownership, and lifecycle facts. | PRD-002, PRD-003 |
| Step Rerun Semantics | How rerun chooses start point, invalidates downstream results, preserves evidence, and handles idempotency. | Rerun can corrupt evidence if stale outputs remain valid. | Full redispatch; generic control; DAG-aware rerun command. | Dedicated endpoint/command with DAG-derived `invalidated_step_ids`. | PRD-003 |
| Human Review/Pause Semantics | How review checkpoints, edited output, resume, worker yield, and evidence are represented. | Highest-risk feature gap across DB/runtime/API/frontend/audit. | Block worker; Celery chain/chord gate; periodic reconciliation; DB state machine plus thin resume task. | DB state machine plus thin resume task: persist checkpoint and next pointer, exit worker, resume through a typed command with compare-and-set duplicate protection. | PRD-003 |
| Evidence Export Semantics | Whether evidence export is JSON API, attachment download, or both. | Generated clients currently risk mismatch with runtime response. | JSON only; attachment only; two endpoints. | Pick one based on primary consumer and align OpenAPI. Prefer JSON for SDK. | PRD-004 |
| API Pagination Contract | Whether list endpoints expose `has_more`, `total_count`, or page-count-only `count`. | External clients need reliable pagination. | Document count; add total_count; add has_more. | Add `has_more` unless total count is a product requirement. | PRD-004 |
| AI Builder Prompt-As-Contract | How prompt, tool, knowledge-pack, plan, and repair behavior is reviewed and tested. | Code refactor can silently change LLM behavior. | No prompt tests; exact output tests; obligation/fixture tests. | Test prompt assembly and contractual obligations, not exact LLM prose. | PRD-005 |
| Frontend AI Builder State Owner | Whether route, Service/controller, or Driver owns mutable AI Builder state. | Driver/Service mirroring is a current SSoT violation. | Service/controller owner; Driver owner; route owner. | Run a small spike before editing; if inconclusive, Service/controller owns Svelte state and Driver is stateless transport/SSE decoder. | PRD-006 |
| Compatibility Deletion Policy | What gates allow deleting shims, public API fields, and persisted row fallbacks. | Pre-production allows breaking changes but not careless data cleanup. | Delete all; keep all; classify by contract type. | Classify as import shim, public API, persisted row shape, or external repair; gate accordingly. | PRD-001, PRD-008 |
