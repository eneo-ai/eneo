Five layers, from the person to the kernel

Each layer does one job and refuses one thing. A script only runs when every layer above it has said yes.

1. People and permissionswho may do what

DoesAuthor adds scripts with Manage Skill scripts. User runs them with the existing compute permission. Administrator sets calls per turn under Admin › Skills.

NeverNobody can run a script without the permission and the Function on the assistant. Edit access to a Space is not enough.

2. The Skillinstructions + scripts

DoesA ZIP with SKILL.md and scripts becomes an immutable revision with a digest. Publication is the review gate; the exact package can be downloaded.

NeverA script never changes without a new revision. A Skill grants no tools, no permissions and no data access.

3. Eneothe execution owner

DoesChecks permission, provider and budget on every call. Writes the record first, saves the result before the model sees it, logs the audit trail.

NeverNever runs code itself. Never reruns a script on its own. Never sends an author's script to an external provider.

4. The sealed boxtool runtime

DoesRuns the script in a fresh process: JavaScript in WebAssembly, confined for files and network, 5 seconds, 64 MB. Compiles scripts at upload without running them.

NeverNever runs a job it cannot seal. No network, no files, no imports, no secrets. Reports errors as data, not prose.

5. The hostLinux + container

DoesLinux Landlock enforces the seal (kernel 6.7 or later). The container is read-only and reaches only the backend.

NeverNo second sandbox, no gVisor. The shared kernel is the accepted boundary, and the test suite proves it before anything ships.
